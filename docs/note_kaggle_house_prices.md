# 趣味でKaggleのHouse Pricesに挑戦してみた｜スコアの読み方も初心者向けに解説

> 片手間の趣味でKaggleのHouse Prices（住宅価格予測）コンペをやってみた記録です。
> AIアシスタントに手伝ってもらいながら、ベースライン作成からスコア改善まで一通り。
> 「CV RMSE」とか「Public LB」とか、最初は数字の意味が全然わからなかったので、
> 同じ初心者の人向けに、できるだけ噛みくだいて書きます。

---

## そもそも何をやっているの?

Kaggle（カグル）は、データ分析・機械学習の「腕試しの場」みたいなサイトです。
お題（データ）が配られて、世界中の人が予測モデルを作って精度を競います。

今回挑戦したのは **House Prices（ハウスプライシズ）** という超定番の入門お題。

- **やること**：アメリカ・アイオワ州エイムズ市の住宅データ（広さ・築年数・部屋数・
  ガレージの有無など約80項目）から、その家の **販売価格（SalePrice）を予測する**。
- **配られるデータ**：
  - `train.csv`（1460件）… 家の情報 **＋ 正解の価格つき**。これで勉強する。
  - `test.csv`（1459件）… 家の情報だけ。**価格は伏せられている**。これを予測して提出する。

つまり「正解を見ながら価格の当て方を学んで、正解が隠された家の価格を当てる」ゲームです。

### ここ超重要：これは「正解率」じゃない

最初に勘違いしやすいポイント。これは「◯×クイズで何問正解したか（正解率）」では
ありません。当てるのは**価格という数字**なので、ピッタリ当たることはまずありません。

> 例：本当は 20万ドルの家を、19万5千ドルと予測 → 「5千ドルぶんズレた」

だから評価するのは **「平均してどれくらいズレたか（＝誤差）」**。
**数字が小さいほど、ズレが少なくて優秀** ということになります。
（正解率なら大きいほど良い。今回は逆で、小さいほど良い。ここが一番の引っかかりポイント）

---

## スコアの正体：「RMSE」ってなに?

今回のズレの測り方は **RMSE（Root Mean Squared Error／二乗平均平方根誤差）** という指標。
名前はいかついですが、気持ちは単純です。

1. 1軒ごとに「予測 − 正解」のズレを計算する
2. ズレを2乗する（プラスマイナスを消して、大きなズレをより重く見るため）
3. 全部の平均をとって、最後にルート（√）で元のスケールに戻す

要するに **「平均的なズレの大きさ」** を1つの数字にまとめたものです。小さいほど良い。

### さらにひとひねり：「価格の対数（log）」で測る

House Pricesでは、価格そのものではなく **価格の対数（log）をとってから** RMSEを計算します。
なぜかというと——

- 5万ドルの家で1万ドル外すのと、50万ドルの家で1万ドル外すのは、感覚的に重みが違う
  （安い家の1万ドルは大事件、高い家の1万ドルは誤差の範囲）。
- logをとると「**◯％ズレたか**」という割合で評価できるようになり、安い家も高い家も
  公平に扱えます。

#### 初心者向けの「ざっくり変換表」

logのRMSEは、ざっくり **「平均して何％ズレているか」** に読みかえられます。

| log RMSE | だいたいの感覚（平均的なズレ） |
| --- | --- |
| 0.40 | 約 ±50%（全然当たってない） |
| 0.20 | 約 ±22% |
| 0.15 | 約 ±16% |
| **0.12** | **約 ±13%** |
| 0.10 | 約 ±11% |
| 0.00 | ズレゼロ（＝完璧。現実には無理） |

つまり今回の **0.12** は、ざっくり **「予測した価格が、実際よりだいたい±13%くらいズレてる」**
という状態。20万ドルの家なら ±2.6万ドルくらいの精度感です。趣味なら十分戦えるライン。

---

## 「CV」と「Public LB」の違い

スコアが2種類出てきて混乱しますよね。これは **「測る場所が違う」** だけです。

### CV（交差検証／Cross Validation）= 自分の手元での模擬テスト

提出する前に、自分の手元で実力を測る仕組みです。
正解つきの`train.csv`（1460件）を5つのグループに分けて、

- 4グループで勉強 → 残り1グループで答え合わせ
- これを担当を替えて5回くりかえして、平均のズレを出す

**「本番前の模擬試験」** だと思ってください。提出しなくても何回でもできるので、
「この改造で良くなった? 悪くなった?」をここで判断します。
記事中の **CV RMSE** はこの模擬試験の点数です。

### Public LB（パブリック・リーダーボード）= Kaggleでの本番採点

`test.csv`（価格が伏せられた家）の予測を提出すると、Kaggleが採点して
**Public LB（公開順位表）のスコア** を返してくれます。これが本番の点数。

> ※さらに正確には、提出は裏で「Public用」と「最終評価用（Private）」に分かれていて、
> 最終順位はコンペ終了時にPrivate側で決まります。が、入門段階では気にしなくてOK。

### CVとLBが近いのは「良いサイン」

今回、手元の模擬試験 **CV 0.108** に対して、本番 **LB 0.123**。
だいたい近い数字ですよね。これは **「模擬試験の点数が本番でも再現できている＝
変なズルや過剰な作り込み（過学習）をしていない健全な状態」** という良い証拠です。

もしCVだけ異常に良くてLBが悪かったら、「手元のデータだけに都合よく合わせすぎ
（過学習）」を疑います。

## 実際にやったこと（スコアの伸び）

片手間でやった割には、ちゃんと右肩下がり（＝良くなる方向）に改善できました。

| やったこと | CV RMSE | Public LB | ざっくりの誤差 |
| --- | --- | --- | --- |
| ① まず素朴に1モデル（XGBoost）で予測 | 0.1275 | 0.12727 | 約±13.5% |
| ② 変なデータを除去＋データの形を整える＋4モデル合体 | 0.1084 | 0.12331 | 約±13% |
| ③ モデルを5つに増やして賢く合体（スタッキング） | 0.1083 | 0.12280 | 約±13% |
| ④ 弱いモデルを外し、強いモデル6つの平均に | 0.1080 | 0.12272 | 約±13% |
| ⑤ 本格的な前処理＋6モデルを重み最適化で合体 | 0.1079 | 0.12246 | 約±13% |

ざっくりの中身：

- **外れ値の除去**：「やたら広いのに激安」みたいな例外物件は、学習の邪魔になるので除く。
- **データの形を整える（対数変換）**：極端に偏った数字をlogでならして、モデルが
  読みやすくする。
- **複数モデルの合体（アンサンブル）**：1つのモデルに頼らず、何種類かの予測を
  平均する。みんなで多数決すると安定して当たりやすい、という発想。

### 正直な学び：教科書どおりが正解とは限らない

「これは効くはず」と言われる定番テク（カテゴリの数値化、近隣ごとの欠損補完など）も
試しましたが、**今回のデータでは効果ゼロ** だったので採用を見送りました。
毎回 **CV（模擬試験）で確かめて、良くならない改造はやらない** ——
これが地味だけど一番大事な作法でした。

## で、どこまで行けばいいの?（初心者の目標ライン）

「ゴールが0なら、どこで満足していいの?」という疑問、すごく自然です。目安を置きます。

| スコア帯（log RMSE） | だいたいの位置づけ |
| --- | --- |
| 0.4 前後 | 何もしてない（全部平均で出した）レベル |
| 0.15 前後 | とりあえずモデルを1個動かした初心者レベル |
| **0.12 前後** | **基本を丁寧にやった「趣味なら十分立派」なレベル ← 今ここ** |
| 0.11 前後 | ネット上の上級者お手本（公開ノート）を真似た上位レベル |
| 0.10 以下 | かなり作り込んだ／一部はテクニックを駆使した最上位 |

House Pricesは「入門用の常設お題」で、何千人も参加しています。
そのなかで **0.12 はだいたい上位の入り口あたり**。趣味で片手間なら、ここは
**「ちゃんと分かってやれた」と胸を張っていいゴール** です。

### 0.12から先がしんどい理由（収穫逓減）

スコアは下がるほど、1ミリ下げるのに必要な労力が跳ね上がります。
0.13→0.12 は工夫でスッと行けても、0.12→0.11 は何時間も格闘してようやく、の世界。
模擬試験のブレ幅（fold間のばらつき）も ±0.007 くらいあるので、
**0.108 と 0.109 の差はもう「誤差の範囲」** だったりします。

なので片手間の趣味なら、**「0.12を切ったあたりで一区切り」** が健全。
それ以上は「楽しいからやる」モードで十分だと思います。

### おまけ：0.10以下を目指して分かったこと

「最上位の0.10以下を狙おう!」と本格的な前処理＋6モデル合体まで作り込んでみました。
結果は **LB 0.12246**。④からは少ししか縮まりませんでした。やってみて分かったのは、

- **0.10以下は、多くが「テストの答えが外部で部分的に分かってしまうリーク（裏ワザ）」を
  使った領域**で、純粋に機械学習だけで正攻法だと到達はかなり難しい。
- 強豪が公開しているお手本ノートでも、正攻法だとだいたい **0.115〜0.118** あたり。
- 手元の模擬試験（CV 0.108）が本番（LB 0.122）より良く出ていたのは、前処理で
  train と test を一緒に処理した影響で**CVがちょっと甘く出ていた**ため。
  こういう時は **LBの数字を信じる** のが正解。

結論：**片手間の趣味なら 0.12 前後で胸を張ってOK**。0.10以下はガチ勢＆裏ワザの世界、
と割り切るのが健康的でした。

### 検証：その「裏ワザ（リーク）」を実際にやってみた

「0.10以下はリークの世界」と書いたので、本当にそうか実演してみました。

このコンペの test データは、実は公開されている学術データ
**「Ames Housing データセット」** の一部です。なので物件の特徴（広さ・築年・部屋数など）で
元データと突き合わせると、**伏せられているはずの正解価格をそのまま引けてしまう** のです。

やってみた結果：

| 提出内容 | Public LB |
| --- | --- |
| 正攻法のベストモデル | 0.12246 |
| **リーク（元データで正解を引く）** | **0.00463** ← ほぼ満点 |

99.7%（1454/1459件）の正解を引けました。一発でほぼ満点です。

でもこれ、**機械学習の実力とは1ミリも関係ありません**。ただの「カンニング」です。
賞金のない練習用コンペだから実演しましたが、本来は規約違反。
逆にこの実験から、

- **「LB上位＝強いモデル」とは限らない**（上位の多くはこのカンニング）
- **データリーク（答えがこっそり混ざる現象）がいかに強力で危険か**

がよく分かりました。実務でうっかりリークを混ぜると「手元では神精度、本番で大事故」に
なります。それを体感できたのは、むしろ良い勉強でした。

### うまい人（正攻法トップ）は何をしているのか

正攻法でトップを取る人たちのノートも分析しました（詳細は同梱の
`docs/top_solutions_analysis.md`）。ざっくり言うと、やっていることは我々とほぼ同じで、

- 目的変数を log 変換、歪んだ特徴量も log/Box-Cox で整える
- 外れ値を除く、欠損は「列の意味」に応じて丁寧に埋める
- 正則化された線形モデル（Lasso など）を主役に、木モデルを少量混ぜて合体（スタッキング）

正攻法トップでも **LB 0.115〜0.118** あたりが相場で、我々の 0.122 はその入り口。
特別な裏技があるわけではなく、**基本の積み重ねを丁寧にやり切った人が強い**、という
当たり前で少し安心する結論でした。

## まとめ

- これは **正解率じゃなくて「価格のズレ（誤差）」** の勝負。**小さいほど良い**。
- スコア（log RMSE）は **「平均で何％ズレてるか」** に読みかえられる。0.12 ≒ ±13%。
- **CV = 手元の模擬試験／Public LB = Kaggleの本番採点**。両者が近いと健全。
- 改造したら必ず **CVで効果を確認**。教科書テクも効かないことがある。
- 趣味なら **0.12前後で十分立派**。そこから先は収穫逓減なので、楽しめる範囲で。

片手間でも、順を追って測りながらやれば、ちゃんと「上達した実感」が数字で見えるのが
Kaggleの面白いところでした。同じ初心者の方の参考になればうれしいです。
